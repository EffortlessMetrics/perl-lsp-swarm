# v0.18 public-beta experience contract

Controller: #5900  
Release controller: #4343  
Freeze authority: #5888  
Installed acceptance: #4346

## Purpose

The v0.18 release must be technically correct and coherent as an installed user
journey. Component passes do not compensate for a broken transition, stale exact
answer, unsafe edit, wrong binary, silent startup failure, or leaked process.

`public_beta_experience.v1` is the product-level conjunction. It references and
validates independent child receipts rather than reimplementing their evidence.
It has no publishing authority.

## Supported envelope

The candidate declares:

- VS Code as the first-class installed experience;
- ordinary standard-LSP compatibility for other editors without an equivalent
  UI-polish claim;
- a finite representative project-family set;
- the accepted core loop:
  diagnostics, completion, hover, definition, references, symbols,
  edit/re-query, formatting, and safe rename or refusal;
- conservative dynamic-Perl fallback or refusal with an intelligible reason;
- DAP as preview.

The validator requires the complete core-loop set. A release note cannot silently
omit a difficult cell and retain `ready`.

## Required journey cells

```text
install_upgrade
startup
workspace
completion_hover_navigation
diagnostics
empty_results
rename_delete
formatting
doctor_trust
dap_preview
shutdown
```

Each cell records one owner issue, one or more candidate-bound evidence
references, and a disposition:

- `pass`;
- `limited` with an explicit limitation;
- `failed`;
- `not_proven` with an explicit limitation.

A limited DAP preview is acceptable. A failed cell blocks. A not-proven cell
prevents readiness.

## Zero-budget trust invariants

```text
false_exact                 = 0
stale_exact                 = 0
unsafe_edit                 = 0
unexplained_success_empty   = 0
silent_startup_failure      = 0
broken_documented_install   = 0
wrong_binary_or_version     = 0
orphaned_server_or_debuggee = 0
```

The fan-in computes `blocked` if any count is non-zero. No weighted score or pass
in another rail can compensate.

## Required child receipts

The fan-in requires references for:

- user-state presentation (#5901);
- first-ten-minutes observation (#5902);
- install/upgrade/recovery/rollback (#5903);
- exact installed acceptance (#4346);
- first useful/correct answer (#4048);
- representative workload (#4050);
- release topology (#5889);
- release integrity (#4145).

Every reference carries schema, digest, candidate identity, status, and claim
boundary. Cross-candidate evidence fails closed. A blocked child blocks the
fan-in; a not-proven child prevents readiness; a limited child remains visible.

Each child reference also names a repository-relative artifact. The validator
reads the bytes, recomputes the SHA-256 digest, parses the verified child
envelope, and checks its schema, candidate ID, frozen product SHA, artifact-set
ID, status, claim boundary, and limitation against the fan-in reference.
Absolute paths and parent-directory traversal are rejected. This proves
artifact consumption and identity binding; it does not replace the child
validator that produced the artifact.

The verified envelope may additionally bind the raw source receipt through a
source artifact path and digest. When that provenance is absent, the fan-in is
`not_proven` even if the envelope itself says `pass`; the checked-in public-beta
fixture intentionally exercises this fail-closed state until every child
validator publishes its canonical source receipt.

## Validation

```bash
cargo test -p xtask --example public_beta_experience
cargo run -p xtask --example public_beta_experience -- \
  --receipt fixtures/experience/public_beta/ready.json
cargo test -p xtask --example pre_freeze_public_beta_acceptance
cargo run -p xtask --example pre_freeze_public_beta_acceptance -- \
  --packet <pre-freeze-public-beta-acceptance.json>
```

The pre-freeze packet is an execution contract for #6056. Its validator checks
candidate identity, release-shaped artifact declarations, required platform and
journey coverage, mechanism dispositions, zero-budget counters, and the
fail-closed freeze recommendation. It does not substitute for running the
packaged artifacts or independently verifying their hashes; those observations
remain required inputs to the packet.

The checked-in `ready.json` currently returns `not_proven` because the fan-in
fixture has not yet been populated with canonical source receipts for every
required child. A future candidate may claim `ready` only after every child
reference has complete source provenance and its own validator result.

The negative fixture and mutation-style tests establish that:

- a wrong binary or failed install transition blocks;
- a hand-written ready verdict cannot conceal a non-zero trust count;
- a child receipt from another candidate is rejected;
- limited cells require explicit limitations;
- missing journey cells fail closed.

## Release transitions

```text
release-shaped product observation
→ child receipts bind one candidate
→ public-beta fan-in computes ready / blocked / not_proven
→ #5888 may freeze only the proven product identity
→ #4350 repeats the exact synchronized candidate
→ #4351 verifies the same journey from public channels after authorization
```

A substantive product mutation invalidates the affected product receipts and the
fan-in. A release-instrument-only failure returns to its narrow release owner.
Neither case is hidden by an unrelated green component.

## Claim boundary

A `ready` receipt establishes the declared v0.18 VS Code public-beta envelope for
one exact candidate and artifact set. It does not establish GA/stable maturity,
all-editor or all-framework parity, complete compiler compatibility, DAP parity,
or permission to tag or publish.
