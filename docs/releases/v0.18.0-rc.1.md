## Summary

First public-alpha release candidate on the v0.18 train. The delta from the
shipped public `0.17.0` beta is large: a native parser and semantic pipeline
now back the language server, the native critic feeds diagnostics directly,
and whole-document formatting is the single supported formatting route. The
VS Code extension is the first-class installed path; other editors remain
secondary. This candidate exists for a short RC observation window — it is
not GA, not production-ready, and not a stability promise.

## Highlights

- VS Code extension as the documented, first-class install path
  (VSIX/marketplace topology); other editor integrations remain secondary.
- Native LSP with daily-driver public-alpha posture: navigation, completion,
  workspace symbols, rename, inlay hints, and semantic diagnostics.
- Native critic diagnostics routed through the LSP diagnostic surface.
- Whole-document formatting only. Secondary formatter routes (range and
  multi-range edits, `source.organizeImports`) are intentionally withdrawn
  for this candidate; they were not carried into the frozen product.
- DAP included as **preview**: lifecycle and store coverage exists, but it is
  not at parity with mature debug adapters.
- Remote AI features fail closed: they cannot arm from generic or project
  configuration without a trusted adapter.

## Known limitations (public alpha)

- No GA, production-readiness, or stability claim is made for this candidate.
- LSP 3.18 compliance is partial; the server does not claim full protocol
  coverage.
- No all-editor parity: VS Code is the primary supported path.
- Parser coverage is not all-Perl exactness; dynamic Perl boundaries remain
  represented as confidence-marked results.
- DAP is preview-grade; mature DAP parity is explicitly not claimed.
- Formatting is whole-document only; withdrawn secondary routes return in a
  later train only with proven cohorts.
- Remote AI stays disarmed unless a trusted adapter is configured.
