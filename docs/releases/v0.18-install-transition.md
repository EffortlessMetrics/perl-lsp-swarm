# v0.18 install-transition evidence contract

Issue: #5903  
Parent experience contract: #5900  
Release topology authority: #5889  
Candidate rehearsal: #4350  
Public-channel verification: #4351

## Purpose

A clean install does not establish that an existing public-beta user can upgrade,
recover from an interrupted managed-binary replacement, reject an incompatible
artifact, or restore the previous usable pair. This contract records one exact
transition from the release topology and computes whether its intended outcome
was achieved safely.

The validator consumes a receipt. It does not select release subjects, download
an artifact, mutate an installation, publish a channel, or authorize a release.

## Topology boundary

Each receipt binds:

- frozen product, prepared swarm, and release-repository SHAs;
- the exact `release_topology.v1` digest;
- one topology path ID;
- previous and candidate versions;
- extension, server, and DAP candidate versions;
- platform and target.

The install matrix is derived by #5889. This receipt cannot add a target or path
that the topology does not own.

## Transition classes

```text
clean_install
normal_upgrade
cached_old_binary
version_or_target_mismatch
interrupted_install
rollback
channel_identity
```

A transition declares one intended disposition:

- `applied` — the verified candidate becomes the effective release identity;
- `rejected` — an invalid, incompatible, unavailable, or incomplete candidate
  is refused while the known-good pair remains usable;
- `rolled_back` — the prior supported extension/binary pair becomes effective
  and no candidate process or ready state survives.

## Safety invariants

The computed result blocks when any transition:

```text
promotes a partial artifact
reports mixed extension/server state as ready
selects an unsupported target as fallback
leaves a candidate process running after rejection or rollback
loses the known-good prior binary
applies an unverified artifact
resolves a documented primary path to the wrong asset
fails to restore the previous release identity during rollback
```

A deliberately rejected corrupt or incompatible candidate can pass when the
rejection is the intended disposition and preserves the known-good state.

## Historical regressions

The fixtures include the publication-repository PowerShell installer incident in
which the documented script constructed an obsolete `perl-lsp-*` asset name while
the release published `perllsp-*`. That packet computes `blocked`; source-tree
correctness cannot substitute for the exact route users execute.

Additional candidate runs should cover:

- stale v0.17 managed-binary cache after extension upgrade;
- omitted `perl-dap` artifact;
- cargo-binstall/download metadata disagreement;
- wrong target or architecture;
- checksum failure and partial write;
- permission failure;
- rollback after candidate startup;
- equivalent identity across every required primary channel.

## Validation

```bash
cargo test -p xtask --example install_transition
cargo run -p xtask --example install_transition -- \
  --receipt fixtures/experience/install_transition/normal_upgrade.json
```

The checked-in fixtures prove:

- a coherent v0.17.0 to v0.18.0 upgrade passes;
- a corrupted candidate can be rejected safely without replacing v0.17.0;
- the historical PowerShell 404 path blocks;
- mixed-version readiness cannot be represented as pass;
- rollback must restore the prior release identity.

## Release placement

#4350 runs the no-publish transition matrix against the exact synchronized
candidate. After explicit release authorization, #4351 repeats every required
primary path from the real public channels. A display version or successful
workflow dispatch is not sufficient; the effective artifact identity and
transition behavior must agree.

## Claim boundary

A validated receipt proves one topology-owned path and transition class for one
candidate, platform, and target. It does not establish all secondary package
managers, automatic migration of arbitrary unsupported configuration, general
auto-update behavior, GA compatibility, or release authorization.
