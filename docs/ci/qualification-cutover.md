## Accepted lifecycle

```text
cheap development and source publication
-> focused/affected proof, substantive review and joined repairs in-session
-> exact-head product/scope judgment and conditional landing authorization
-> verified native enqueue
-> selected integration qualification on actual merge-group G
-> protected native landing
-> cheap landed M reconciliation
```

At enqueue, the intended candidate is already locally green and reviewed. This
does not preclude a genuine integration defect or useful later challenge. A
material finding withdraws eligibility; qualification failure returns to the
specific repair/proof owner. Do not add a compulsory post-green approval pause
or a second direct merge. Keep useful warm context and the selected model through
ordinary waits; a capacity failure is not authority to switch models.

## First-installation decision

Before apply, #17080's packet must name the **first source-to-protected-main
operation** and its actual trusted producer. "Install the source" is not that
operation. Record the precise missing capability or incompatible predicate when
no supported route is established. Keep affected admissions held; independent
local implementation, review and verified safe source preservation may continue.

The packet contains three coordinated generations:

| Generation | Prior, desired and rollback observations |
| --- | --- |
| Source | Main/candidate/tree, reviewed change set, product and metadata roots, indirect edges, reusable pins, required-context producers, agent command and rollback bytes. |
| Enforcement | Complete applicable protection/rulesets, queue configuration, required names/application bindings, bypass treatment, and authorized operator scope. |
| Workflow enablement | Native workflow IDs/paths/states, inventory completeness, separately governed roots, in-flight runs/attempts, and intended state for each phase. Preserve workflows already disabled. |

Stage and test the complete compatible source before any live mutation. Source,
settings and workflow-state writes are separate transactions: observe each result,
refuse mixed-generation admission, and preserve evidence after partial failure.
An exact local receipt cannot stand in for a protected check or an applied setting.

### Workflow disabling is a candidate containment primitive

Native workflow disabling prevents new triggers without deleting source. GitHub
states that existing runs are not cancelled, but cannot be rerun while disabled.
That makes it worth qualifying for first installation; it is **not an accepted
live sequence** and does not satisfy required checks by itself.

The bounded experiment must hold ordinary publication and relevant metadata/event
producers, not merely queue admission. Capture all affected workflow states and
in-flight work; disable only authorized roots; observe the boundary before relying
on it for source publication. Then prove how the exact-H publisher and required G
producers remain usable. Do not implement a fast enable/disable race and assume
it is safe.

Qualify early completion/landing, delayed indirect events, reusable/finalization
paths, ejection/retry, cancellation, new/renamed workflows and partial rollback.
Whether enabling replays prior events is unproved here. Zero jobs or an empty
filtered CLI listing is not zero workflow runs: include disabled workflows and
complete pagination in native observations. If the mechanism cannot preserve the
accepted boundary, reject that ordering rather than infer a bootstrap exception.

## Authorized canary and acceptance

Once the exact packet and native canary are authorized, keep admissions held while
the designated operator applies and reads back the compatible generation. Initial
queue build concurrency one and one-entry landing, SQUASH/ALLGREEN, describe the
bounded canary, not a permanent global development limit or singleton membership
proof. A fresh effective-settings read must establish the actual values.

The canary must establish genuine H admission; actual G/base/constituents and
selected scope; every required named/application-bound G result; incomplete,
wrong-subject/attempt and failed-obligation refusal; and protected G-to-M landing.
Only a demonstrated compatible enforcement generation can make cheap admission
safe: it must never protect a direct-merge alternative.

Reconcile M against the tested integration without replaying qualification merely
because landing occurred. Demonstrate zero workflow runs on ordinary lifecycle
and generated-publication paths. Keep separately admitted deep, incident, security,
cache and release propositions with their owners. Time or merge count alone does
not authorize another whole-suite run.

Measure complete active qualification, including setup, compilation, transfer,
verification and finalization, against the normal <=20-minute target. Report
queue delay, machine-minutes, cold/warm context, retries/cancellations and cost per
accepted landing separately. A source fixture or lower workflow count is not a
runtime or economic acceptance result.

## Rollback

Hold new admissions and ordinary event producers while reconciling in-flight
work. Preserve actual failures and original receipts. Use the reviewed rollback
packet to restore compatible **source, enforcement and workflow enablement**;
read back each operation before reopening admission. Do not force-reset main or
delete check history. Restore only the intended prior workflow states.

A prior source generation may contain ordinary PR/push subscriptions. Preserving
or restoring its bytes does not authorize executing those subscriptions. If the
prior source, protection and workflow states cannot jointly maintain the current
no-development-CI boundary, remain held with that precise incompatibility. There
is no temporary ordinary-lifecycle bootstrap or rollback exception.

Before removing queue-only enforcement, prove that compatible full-proof rails
are restored; never leave cheap admission protecting direct merges. If historical
patch preimages changed, prepare a reviewed contextual revert rather than forcing
an obsolete exact-reversal patch. Source rollback alone is not runtime rollback.
