It creates no manifests, no cluster harness, no DAP behavior, no support verdict, and no sidecar admission. DAP cell rows reference current exact evidence sources; they are not new behavioral proof.

## Security and ownership requirements

- **`parent_owned_stdio_no_shell_no_tty`:** stdin/stdout are owned by the parent with no shell and no TTY between parent, adapter, and debuggee.
- **`no_kubernetes_credentials_to_adapter_or_debuggee`:** No Kubernetes credentials reach the adapter or the debuggee.
- **`service_account_token_absent_or_unused`:** The projected ServiceAccount token is absent, or mounted and provably unused according to the profile.
- **`no_network_listener_created_for_dap`:** No network listener is created for DAP by the adapter or the debuggee.
- **`explicit_uid_gid_and_path_ownership`:** UID/GID, writable paths, and temp/cache/home ownership are declared explicitly.
- **`process_tree_and_pod_cleanup_owner`:** Both the debuggee process tree and the pod have one named cleanup owner.
- **`secrets_redacted_from_retained_receipts`:** Secrets and private paths are redacted from retained receipts.
- **`workspace_data_cannot_select_adapter_or_cluster_target`:** Workspace-controlled data cannot select another adapter binary or a different cluster target.

## Limitations

- No cluster, pod, or debug session is executed by this contract; kind execution, live probes, and manifests that run the adapter remain future work.
- Sidecar topologies are rejected here even when they share a pod; proving identical source and project-Perl parity is a separate claim.
- DAP cell rows are evidence references into current perl-dap proof surfaces; this contract promotes no capability and creates no support row in #7122.
- loader os is declared, not machine-compared against the subject identity
