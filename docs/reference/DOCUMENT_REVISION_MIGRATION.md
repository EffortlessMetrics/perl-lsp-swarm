# Checked document revision migration inventory (#10247)

Source pin: `23f41d647da21ccf679d1e5bbcfd96efdb06f1d0`. This is a reviewable migration inventory, not a runtime
registry, execution receipt, or claim that production has migrated. #8286 owns
cutover; #8384 owns DocumentStore; #8657 owns accepted atomic source commit.

The new private `state::document_revision` module stages immutable checked
primitives only. Its initial generation is 0; this is a primitive initial value,
not admission to the existing index API where nonzero generations are required.
The eventual store decides when an accepted open receives that revision and how
its downstream representation migrates. `checked_next` produces a candidate;
only the commit owner installs it. Discarded candidates create no accepted state.

The one production instance allocator is process-global and has no reset API.
Tests use isolated synthetic allocators only. MAX is issued once; subsequent
allocations fail. Generation MAX is reachable and has no successor. Reopen with
identical content receives another instance. Bare generation ordering is not
exposed; comparison checks the instance. Observation ordinals are explicitly
current-process-only, not wire/global identity, and no serde conversion exists.
The public semantic `DocumentInstanceId` is deliberately unchanged.

## Load-bearing writers and comparisons

- `state/document.rs`: `next_document_incarnation` uses unchecked AtomicU64;
  `new`/`from_parts` allocate incarnations, `generation` remains Arc<AtomicU32>.
  `mark_full_sync_required`, `update_content`, `apply_change` advance it;
  `replace_text_state` assumes its caller already advanced it. `observe_change_version`
  modifies the accepted-version field as a rejected-input watermark. #8286/#8657
  replace accepted-source writers; #8666 separates currentness invalidation.
- `runtime/text_sync.rs`: didOpen creates FIRST_ACCEPTED_DOCUMENT_GENERATION;
  didChange calls the invalidation writer or raw fetch_add/wrapping_add, later
  installs reconstructed state. Async/synchronous parser and indexing paths
  capture that counter. `document_generation_still_current` compares Arc identity
  and numeric generation. #8657 must own source commit; #7247/#7375/#7379 own tickets.
- `runtime/parse_worker.rs`: ParseJob/predecessor and PublishedParseTicket carry
  generation/instance handles. Publication validates Arc identity then calls
  `publish_parsed_if_current`. Do not replace parser operation IDs with source IDs.
- `runtime/diagnostics_sink.rs`, `document_symbols_sink.rs`, `scheduler.rs` and
  `document_access.rs`: document-dependent sink/response/index comparisons must
  move together with their source subjects. Pointer identity is an interim
  implementation guard, not a durable identifier. Workspace/config counters in
  the same files remain different domains.
- `runtime/text_sync/lifecycle.rs`: close resets index generation; save captures
  current generation and Arc lifetime then revalidates before index admission.
  Root removal/shutdown in workspace/lifecycle code retire that same source;
  no callback may resurrect a closed instance.
- `runtime/parse_effect_contract.rs` bridges the local incarnation into the public
  semantic identity. #8286 must explicitly bridge the new opaque identity rather
  than add From conversions or claim a local ordinal is globally durable.

`generation|incarnation|Arc::ptr_eq` at the pin, including inline tests/comments
and standalone tests as a conservative superset. All matched lines are retained
as review coordinates. This is lexical evidence, not compiler-resolved dataflow:
follow calls from each writer/guard above during cutover, and re-run the census
when source moves. Every row has a proposition/role, target owner and removal
condition. Inline tests in a production file inherit its migration owner; they
are not extra production writers. Explicit excluded-domain rows prevent a
mechanical rename of similarly spelled counters. Source aliases in the same
functions (for example next_gen and desync_gen) follow the named writer row.

Reproduce the denominator before adding the staged module:

```powershell
rg -n 'generation|incarnation|Arc::ptr_eq' crates/perl-lsp-rs/src --glob '!**/document_revision.rs'
```

No production reader/writer in this denominator is omitted because it is hard to
migrate. Removing a row requires reviewing its disappearance or recording the
replacement authority. This inventory does not assert broader workspace-wide
parser/workspace generations are document generations.

## Proof and limits

Seven fallible primitive tests cover sequential/concurrent allocation, exhaustion,
same-instance comparison, reopen, source-independent advancement and bounded
observation. Compile-time negative controls reject bare ordering, raw/client
conversion and serialization. These are model tests: they do not establish real
open admission, production rollback, parse/effect freshness, full-sync recovery,
installed behavior or any release acceptance. Those remain with the owners above.

The scoped staged-use expectation in state/mod.rs is removed by #8286 when the
first production consumer lands. It is not a blanket permission for unused
runtime models. Rollback deletes the private module, its declaration and this
inventory; runtime behavior is unchanged.
