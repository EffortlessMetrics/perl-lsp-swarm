## Authority boundary

The Test2-specialized path must distinguish five cases:

```text
known module + known ordinary export
    -> admit according to the reviewed default/optional/tag/rename contract

known module + known generated-import rule
    -> admit only when parser-backed arguments prove the generated local name

known module + unknown requested export
    -> refuse the unsupported Test2 fact

unmodeled first-party Bundle/Tools namespace
    -> emit no specialized Test2 fact

dynamic or external plugin namespace
    -> use a separate generic evidence path, never pinned first-party truth
```

A source-spelled import is a request, not evidence that the module exports or
installs that name. Ordinary `Exporter` / `Test2::Util::Importer` symbols and
helpers generated by custom importer code are separate fact classes.

| `Test2::Bundle::Extended` | On by default | On by default | It inherits V0's importer and its pragma opt-outs. |
| `Test2::Bundle::More` | No caller effect | No caller effect | It uses ordinary `Exporter`; its own `use strict; use warnings;` is module-scoped. |

## Bundle-selected behavior is not standalone behavior

The source repeatedly selects a subset or superset from another module. The
implementation must keep these identities separate:

- V0 selects only `cmp_ok` from `Test2::Tools::ClassicCompare`, while the
  standalone module defaults all six classic comparison functions.
- V0 selects `intercept` and `context` from `Test2::API`, while plain
  `use Test2::API;` imports nothing.
- V0 selects optional `refcount` in addition to the two standalone Refcount
  defaults.
- V0 renames `subtest_buffered` from `Test2::Tools::Subtest` to local
  `subtest`; that does not redefine the standalone tool's defaults.
- `Test2::Bundle::Extended` aliases V0's export array; it is not an empty or
  absent compatibility namespace.

A single per-symbol list is therefore insufficient unless it carries module,
selection mode, local name, and ordinary-versus-generated provenance.

## Target generated-symbol contract

`Test2::Tools::Target` installs package symbols rather than exporting a fixed
menu:

```perl
use Test2::Tools::Target 'Some::Package';
# $CLASS and CLASS()

use Test2::Tools::Target service => 'Some::Service';
# $service and service()

use Test2::Tools::Target {
    reader => 'Some::Reader',
    writer => 'Some::Writer',
};
# $reader / reader() and $writer / writer()
```

V0 and V1 delegate their `-target` option to the same importer. Static support
must preserve the ordinary bundle exports and add only the locally generated
names whose argument shape is proved. Dynamic expressions, malformed pairs,
unclosed structures, or unknown keys fail closed; package/value atoms do not
become imports.

The runtime importer also requires each target package. The LSP does not
execute that require and must not claim runtime load success.

## Required proof before promotion

The implementation and production-completion route must cover, for each
supported module shape where applicable:

1. plain/default import;
2. explicit known import;
3. explicit unknown import;
4. `:DEFAULT` and `:ALL`;
5. exclusion;
6. `-as`, prefix, and postfix local names;
7. explicit empty import `()`;
8. V0/Extended caller pragma defaults and opt-outs, plus opposite controls that
   More, Simple, Suite, and V1 do not enable caller `strict` or `warnings` by
   default;
9. bundle-selected versus standalone defaults;
10. direct and V0/V1 Target helpers;
11. dynamic and malformed Target refusal;
12. unknown first-party namespace negative controls;
13. stable Test2 provider/authority identity in production completion rows.

#13225 must independently load the pinned distribution and report the observed
local symbols for cases where custom importers, aliases, or compile/load order
could change the static reading. #13226 must retain both false-positive and
false-absence regressions, including the invalidated #13163 claims.

## Update and invalidation rule

This receipt is valid only for the exact commit above.

When the Test2 pin changes:

1. record the new repository, commit, and distribution version;
2. diff every inspected source path and the bundle composition;
3. regenerate or re-review the module/import/generated-symbol matrix;
4. run the independent runtime oracle before changing accepted facts;
5. run resolver and production-completion falsifiers;
6. update this receipt and the implementation in the same reviewed train, or
   mark the affected rows `NOT_PROVEN`.

A newer release, current MetaCPAN page, user-spelled import, or prior LSP table
does not silently override the pinned subject.
