The Zed programme has two control objects with different jobs:


The stable topology changes only when the architecture changes. Ordinary merges, issue closures, CI results, external review, and elapsed time change the observation, not the DAG.

## What the first implementation attempt taught us

The replacement train preserves the useful work already landed while correcting the failure classes exposed by the first pass.

### Historical branches are not dependency authority

The original implementation was built as a stack of branches. As `main` advanced, child PRs inherited stale ancestors, unrelated history, temporary branch-writing workflows, and contradictory status. The correct unit is now:

```text
one issue
→ one bounded current-main increment
→ one canonical draft PR
→ merge
→ reconstruct the next stage from the new main
```

Old branches and PRs remain patch-mining and historical subjects. #10352 records their unique work and canonical successors.

### Authority is not execution

Schemas, validators, source code, WASM builds, release metadata, and checked `not_run` templates are authority to run an experiment. They are not the experiment result.

The train therefore separates every implementation authority from its executable evidence PR:

```text
asset producer       != asset receipts
host driver          != host receipt
settings experiment  != settings behavior
provider-order model != provider-order evidence
managed-route model  != first-mile/recovery evidence
public driver        != public official-registry journey
```

### Exact subjects must be constructed, not asserted

An operator-supplied extension directory and WASM path can bind what was run, but cannot prove that the directory was built from the reviewed upstream base and repository-owned candidate without unreviewed edits. #10392 materializes and attests the development-extension subject before host execution.

### Host cells must be derived from evidence

A free-form observation file is not a reliable truth source. #10393 derives required receipt cells from immutable logs, process inventories, deterministic fixture effects, and a narrow content-addressed operator-only allowlist.

### Release projection needs one authority

The captured v0.17.0 asset table usefully froze facts, but it cannot remain a second hand-maintained release topology. #10395 generates the Zed projection from canonical topology plus one reviewed public-release input. Network refresh writes only a candidate input for review.

### Known-good cache safety precedes cleanup

The staged downloader originally removed older versions immediately after extraction. At that point Zed had not proved that the new server launched. #10396 must choose a lifecycle that preserves current and prior-known-good subjects through failed candidates; extraction cannot masquerade as launch success.

### Compatibility is a three-subject result

A Zed build, extension package, and `perllsp` binary may each exist and still be incompatible together. #10394 owns one compatibility policy. #10401 applies it to exact-source and managed-public development-extension receipts; #10478 applies it to the eventual official-registry receipt.

### Public support needs both behavior and distribution

A development extension, public binary, merged upstream commit, registry listing, or released default setting is not an ordinary public installation. #7912 proves the clean official-registry journey. #10478 derives the exact public compatibility row. #8000 may then project only those earned cells.

### LSP and DAP share an extension, not evidence

`perllsp` and `perl-dap` are separate executables, protocols, roles, processes, and support rows. The DAP train is a non-blocking sidecar. No core LSP stage depends on it, and DAP cannot inherit the `perllsp` identity adapter.

## Product identities

```text
perlnavigator-server -> Perl Navigator
perl-lsp             -> tree-sitter-perl/perl-tree-sitter-lsp
perllsp              -> EffortlessMetrics/perl-lsp
perl-dap             -> EffortlessMetrics/perl-lsp debugger executable
```

The language-server IDs are not aliases. Selecting `perllsp` must launch exact `perllsp --stdio`. `.pod` remains assigned to the separate POD language.

## One stage, one PR

Every `codex` or `read_only_acceptance` stage completes through the checked **deliver-PR** contract:

1. Read the owning issue and current comments.
2. Observe current `main` and every merged dependency.
3. Inspect canonical PRs and historical branches only as patch-mining subjects.
4. Observe named external subjects read-only when the stage requires them.
5. State one bounded claim and changed-file map.
6. Write realistic falsifiers before implementation.
7. Reconstruct the narrowest increment on current `main`.
8. Run focused and applicable policy checks.
9. Commit and push intentionally.
10. Open one draft PR and update the issue handoff.
11. Stop before merge or external write unless separately instructed.

Use **Advances** until the issue's actual exit authority is earned. A local branch, unpushed commit, checked template, green source build, or closed issue does not complete a stage.

Each handoff records:

```text
exact base and subject identities
changed-file map
commands and results
non-pass cells and limitations
dependency and invalidation state
next unblocked train stages
```

## Evidence boundaries

These substitutions are forbidden:

```text
manifest or WASM build          != actual Zed behavior
arbitrary extension directory   != attested extension subject
free-form observation           != immutable evidence derivation
version output                  != canonical binary identity
canonical packet                != observed file SHA-256
release metadata                != downloaded executable bytes
public executable smoke         != real Zed host behavior
development extension           != official registry distribution
registry submission             != registry publication
registry publication            != released Zed defaults
merged source                   != public availability
PATH route                      != managed route
one platform                    != another platform
server capability               != observed Zed method
static defaults patch           != quiet provider behavior
receipt template                != executed receipt
subject existence               != compatibility
submitted external PR           != accepted upstream subject
LSP evidence                    != DAP evidence
```

Unknown, missing, stale, skipped, cancelled, timed out, malformed, cross-subject, or instrument-failed evidence remains non-green.

## Stop conditions

Stop and report the exact blocker rather than broadening the PR when the proposed work would:

- create a second train, release, identity, evidence, compatibility, cache, support, or packet authority;
- depend on a stale branch instead of merged current-main contracts;
- require an arbitrary extension tree or unbound executable;
- convert operator prose into a required pass;
- adopt an untested latest release or platform;
- delete prior known-good state before observed promotion;
- collapse managed and PATH, exact-source and public, or one platform into another;
- infer compatibility from matching versions or package presence;
- weaken a baseline, gate, denominator, or claim for green;
- make DAP block or satisfy core LSP;
- require an upstream, registry, release, tag, package, or remote-branch write.
