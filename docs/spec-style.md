# Spec Style Guide

Use this guide for repo-owned rails in `.perl-lsp-spec/`.

## Rules

- Prefer measurable statements over slogans.
- Add explicit claim boundaries for comparative or temporal statements.
- Distinguish historical evidence from current behavior.
- Put durable specification truth in `.perl-lsp-spec/`; keep process help in `docs/`.
- Put live operational policy ledgers in `policy/` when applicable.
- Treat `.codex/`, `.spec/`, `.claude/`, `.jules/` as external/tool awareness namespaces, not durable owned truth.
