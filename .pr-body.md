## What this does

`LspServer` kept three session-scoped warning-dedup sets as unbounded `HashSet<String>` (`critic_workspace_warnings_sent`, `client_setting_warnings_sent`, `ai_backend_warnings_sent`). Their key domains are client/environment-controlled (configured profile paths, editor-provided setting values, subprocess error text), so a long-lived or adversarial session could grow retained memory without limit and the raw strings (including absolute paths and error bodies) were retained verbatim, even though only `window/showMessage` suppression was at stake (#9769).

**Fix:** one typed `SessionWarningDedupStore` (`runtime/session_warning_dedup.rs`) whose only authority is whether an already-emitted warning should be suppressed for the same reviewed subject:

- **Typed fixed-size identity** — `(SessionWarningCode, SessionWarningSubjectTag, u64 fingerprint)`, 16 bytes, `Copy`. No raw value, path, error body, or secret-bearing payload is retained; the fingerprint is the repository's shared deterministic FNV-1a (`fnv1a64`, extracted beside the existing `fnv1a64_hex` in `perl-lsp-rs-core::hashing`).
- **Reviewed bound semantics: per-family bounded saturation.** Hard cap of 32 identities per family (`PER_FAMILY_ENTRY_CAP`); a family that is saturated still *emits* every new actionable warning (`EmitWithoutRetaining`) and simply stops retaining, so growth halts at `32 × 16` bytes per family and a full table can never silently drop a warning. No eviction: within the cap, suppression stays stable for the session, preserving the warn-once wording intent.
- **Family-local lifecycle** — the critic family clears on critic configuration transitions and the AI-backend family clears on configuration notifications, exactly at their existing call sites; `clear_family` cannot touch another family. Correctness never depends on the clears (the hard cap is load-bearing). Unknown/unrepresentable client-setting names fail to the bounded emit-without-retaining path rather than storing an arbitrary string.
- **One store for push *and* pull** — review found `PullDiagnosticsOrchestrator` keeping a fourth unbounded `warnings_sent: HashSet<String>` with raw `execution-failed:{e}` error bodies on the pull-diagnostics path; it now routes the same three critic warning shapes through the shared bounded Critic family (its private set is removed), and the xtask negative control also fails if a `warnings_sent` store reappears in `runtime/diagnostics.rs`.
- **Reservation atomicity** — `notify_ai_auth_failure` decides, sends, and rolls back inside one family-lock hold (`emit_once_with`), restoring the pre-#9769 guarantee that a concurrent auth failure can never suppress against a reservation whose send has not succeeded.
- **Counters for #9183** — `LspServer::session_warning_dedup_snapshot()` exposes per-family `entries`, `high_water_entries`, `inserted`, `suppressed`, `emitted_without_retaining`, `cleared_by_lifecycle` under `expose_lsp_test_api`/test.
- **Unchanged:** warning wording, remediation text, warn-once decision policy, one-shot atomics, and every semantic surface (the store is consulted only by the three emit paths).

**Registry (#9155/#7931):** registered in `docs/large-workspaces/RETAINED_STATE_INVENTORY.md` as provider_or_presentation/operational-session state — semantic authority none, lifecycle server session + applicable subject, persistence never, hard bound explicit (32 × 16 bytes per family), privacy no raw secret/value/path payload.
