## Intent

Harden three DAP security surfaces identified in issue #4638:
1. `validate_source_path` bypass when `workspace_root` is `None` (pre-launch window)
2. `handle_attach` accepting any `pid > 0` without existence verification
3. `is_valid_perl_interpreter` using loose `starts_with("perl")` matching

## Controlling issue

#4638

## Scope

- `crates/perl-dap/src/debug_adapter/mod.rs`: `validate_source_path` `None` arm now rejects paths containing `Component::ParentDir` (`..`); absolute paths outside CWD are warned but allowed (no workspace boundary is known — temp files and explicit user paths are legitimate pre-launch use cases).
- `crates/perl-dap/src/debug_adapter/process.rs`: Added `verify_attach_target(pid)` helper using `signal::kill(Pid, None)` (Unix) / `OpenProcess` (Windows) to verify process existence before storing PID or emitting stopped event. Non-existent PIDs are rejected; `EPERM` (foreign user) warns and proceeds.
- `crates/perl-dap/src/debug_adapter/process/perl_spawn.rs`: Replaced `starts_with("perl")` with strict regex `^perl(\d+(\.\d+)*)?$` via `LazyLock<Result<Regex>>` (allowed exception). Admits `perl`, `perl5`, `perl5.38`, `perl5.38.2`; rejects `perlevil`, `perlscript`, `perl_backdoor`.
- `crates/perl-dap/Cargo.toml`: Added `winnt` and `handleapi` to winapi features for `PROCESS_QUERY_LIMITED_INFORMATION` and `CloseHandle`.

## Non-goals

- Changes to the workspace-root-set path validation path (already secure via `security::validate_path`).
- Changes to TCP attach mode.
- Changes to the bridge adapter.

## Change shape

- 3 production source files modified (mod.rs, process.rs, perl_spawn.rs)
- 1 Cargo.toml updated (winapi features)
- 1 new test file: `dap_security_path_bypass_4638.rs` (8 tests)
- 5 existing test files updated to use `std::process::id()` instead of hardcoded non-existent PIDs, plus new PID verification tests
- Updated inline interpreter validation tests with negative assertions for look-alike names

## Claim boundary

The path validation fix blocks `..` traversal in the pre-launch window. Absolute paths outside CWD are warned but allowed because no workspace boundary is known and temp files are legitimate pre-launch use cases. This is a defense-in-depth improvement, not a complete sandbox.

## Risk and rollback

- **Risk**: Low — changes are additive (new validation in previously-unvalidated path, new verification before previously-unchecked attach, stricter regex for previously-loose matching).
- **Rollback**: Revert the commit. Existing tests that were updated to use `std::process::id()` will need to be reverted too.
- **Behavioral change**: `handle_attach` now rejects non-existent PIDs. Tests using hardcoded PIDs (7777, 8888, 9999, 12345) were updated to use `std::process::id()`.

## Remaining work

None — all three sub-issues from #4638 are addressed with tests.
