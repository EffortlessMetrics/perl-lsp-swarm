## Remediation plan for the 46 issues filed in #4614–#4659

A full burn-down, sequenced into 6 waves. Each wave is independently shippable; later waves get cheaper because earlier waves fix the detection gaps that let the later bugs ship.

### How this plan is structured

- **Wave ordering is by leverage, not by severity.** Issues that unblock detection of other bugs come before issues that fix one bug in isolation. The single highest-leverage fix is the test-quality root (#4628 + #4642) — once the integration tests actually run, ~10 other bugs become visible in CI rather than only at user-runtime.
- **One PR per concern** per AGENTS.md § Scoping. Bundled issues (e.g. #4648, #4651, #4657) are split into focused commits within one PR only when the fixes share a file AND a fix shape; otherwise they stay separate PRs.
- **No test weakening to obtain green** per AGENTS.md § Stable authorities. Where a fix requires a test to change, the test is strengthened, not relaxed.
- **Exact-head proof after every substantive mutation** per AGENTS.md. Each PR cites the CI SHA in its body.
- **Each wave ends with a merge batch of ≤3** per CLAUDE.md § Merge and CI, with `gh pr diff --name-only` cross-check for same-file conflicts.

### Cross-cutting fix shapes (reused across waves)

Three fix shapes recur across many issues. Identifying them up front avoids re-deriving the approach per-issue:

1. **Off-lock + cancellation pattern** — snapshot document text under the documents lock, drop the guard, run the expensive work off-lock, poll the cancellation token at iteration boundaries. Unifies #4628 (production fallback leak), #4643 (formatting lock), #4644 (cancellation not polled), #4654 (superseded scan). Template: `crates/perl-lsp-rs/src/runtime/parse_worker.rs:1097-1112` and `mod.rs:1041` (`snapshot_documents_lightweight`).
2. **Reuse `BoundedLruCache`** for #4655 (index eviction). The primitive already exists at `crates/perl-workspace/src/workspace/cache.rs:132`; the fix is to route `WorkspaceIndex` reads through it (or add a parallel bounded structure), not invent new infrastructure.
3. **Apply the existing validator at the missing surface** — the DAP injection cluster (#4637), the silent-enum-typos (#4622), the dead-code terminators (#4656), and the regex `(?#...)` skip (#4659) all have the validator infrastructure already; the fix is to call it on the surface that's currently bypassed.

### Wave 2 — Unblocking roots (test quality + xtask false-confidence)

**Goal:** make CI actually catch the bugs the audit found. This is the highest-leverage wave — once it lands, Waves 3–6 get cheaper because regressions surface in CI instead of at user-runtime. ~6 PRs, ~3 weeks.

The root cause for the test cluster: the real LSP handlers genuinely hang when invoked directly via `LspServer::handle_request` in `lsp_e2e_user_stories.rs` and `lsp_behavioral_tests.rs`. `LSP_TEST_FALLBACKS` was a workaround for that hang, not laziness. The fix is to route these tests through `LspHarness` (which already has adaptive timeouts, `wait_for_idle`, `wait_for_symbol` at `tests/support/lsp_harness.rs:535,585`) instead of direct invocation, then remove the env var.

### Sequencing dependencies (why this order)

```
Wave 1 (security)        — independent, ships first
Wave 2 (test quality)    — unblocks detection for all later waves
Wave 3 (correctness)     — depends on W2 for the tests to validate fixes
Wave 4 (reliability)     — depends on W2-1 (cancellation fix shape)
Wave 5 (release)         — independent of W2-W4; can parallel
Wave 6 (docs)            — fully parallel; no code dependencies
```

**Critical path:** W1 → W2 → W3. Waves 4, 5, 6 can run in parallel once W2 lands.

### What this plan does NOT do

- Does not redesign the diagnostic pipeline (#1773 is referenced but not consumed).
- Does not make the dead-code analyzer AST-based (the fix is to patch the text-scan, not redesign — an AST-based analyzer is a separate epic).
- Does not add OSS-Fuzz integration (mentioned in #4658 but scoped out).
- Does not change the merge-gate required-checks set (that's a policy decision for the maintainers; this plan only fixes the workflow bugs).
- Does not commit to a specific capability-gating contract (#4629) — the plan recommends "gate all 26" but flags it as a design decision for W4-6.

### Total scope

~35 PRs across 6 waves, ~3-4 months elapsed. The single highest-leverage PR is W2-2 (test false-confidence bundle) — it converts ~15 silent regressions into CI failures.
